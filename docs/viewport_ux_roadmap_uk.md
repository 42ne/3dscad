## 🔴 Критичні

### 1. Frame selection / Zoom-to-fit
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.cpp` — `setSelectedIndex` / `setSelectedGroupId`
- **Опис:** Немає автоматичного центрування на вибраному об'єкті. Камера завжди ініціалізується з target=(0,0,0). Додати `frameSelection()`, яка обчислює AABB вибраної фігури/групи та підлаштовує дистанцію + target камери. Прив'язати до кнопки тулбару та гарячої клавіші (F).
- **Тест:** Вибрати фігуру на (100,100,100), натиснути F, перевірити що target камери змістився на (100,100,100) а distance відповідна.

### 2. Гарячі клавіші в'юпорту
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.cpp` — `keyPressEvent` (не перевизначено)
- **Опис:** Перевизначити `keyPressEvent` для частих команд: F (frame selection), R (скинути вигляд), Ctrl+0 (скинути зум), 1-6 (пресетні вигляди), W (wireframe), G (сітка), B (зміна бекенду), V (ортогональна проєкція).
- **Тест:** Поставити курсор у в'юпорт, натиснути F, перевірити frame-selection.

## 🟡 Високий пріоритет

### 3. Ray-cast picking в режимі OpenGL
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.cpp` — `mousePressEvent` / `paintGL`, `viewportglrenderer.cpp`
- **Опис:** Зараз pick buffer створюється тільки програмним рендерером. Коли активний OpenGL, picking запускає повний SW рендер за лаштунками, який може бути застарілим. Реалізувати `glReadPixels`-picking в GL-бекенді: рендерити ID фігур кольорами в offscreen FBO, читати піксель під курсором, мапити на індекс фігури.
- **Тест:** Увімкнути OpenGL, клікнути фігуру, перевірити правильне виділення.

### 4. Пресетні вигляди камери
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportcamera.h` / `viewportwidget.cpp`
- **Опис:** Додати кнопки пресетних виглядів: Front, Top, Right, Back, Bottom, Left. Кожен встановлює фіксований yaw/pitch. Можна реалізувати як невелике спливаюче меню або радіальне меню.
- **Тест:** Натиснути "Front" → камера показує +Z як фронт. "Top" → вигляд зверху.

### 5. Scale гізмо
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportaxisgizmo.h` / `viewportaxisgizmo.cpp`
- **Опис:** Коли вибрана група `Scale`, малювати масштабне гізмо (три осьові ручки + центральний кубик для рівномірного масштабу). Визначати тип операції групи в `pickSelectedTransformAxis()`.
- **Тест:** Вибрати Scale групу, потягнути за ручку X, перевірити що меш розтягується тільки по X.

### 6. Мультивибір у в'юпорті
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.h` — `m_selectedIndex` / `m_selectedGroupId` скалярні
- **Опис:** Замінити на `QSet<int>`. Ctrl+клік перемикає, Shift+клік додає діапазон. Емітувати сигнали мультивибору в дерево та CSG.
- **Тест:** Ctrl+клік двох кубів → обидва підсвічені.

### 7. Wireframe режим
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportglrenderer.cpp` / `viewportsoftwarerenderer.cpp`
- **Опис:** Додати перемикач, який рендерить ребра мешів замість твердих граней. В GL: `glPolygonMode(GL_FRONT_AND_BACK, GL_LINE)`. В SW: малювати трикутники без заливки.
- **Тест:** Увімкнути wireframe → всі меші показуються як дротяний каркас.

### 8. Контекстне меню в'юпорту
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.cpp` — `contextMenuEvent`
- **Опис:** Зараз права кнопка тільки панорамує. Додати меню: Frame Selection, Reset View, Preset Views, Wireframe, Fullscreen, Copy Screenshot.
- **Тест:** ПКМ на порожній області → меню з очікуваними опціями.

## 🟠 Середній пріоритет

### 9. Snap для гізмо (сітка, кут)
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportaxisgizmo.cpp` — обчислення дельти
- **Опис:** Додати перемикач snap. Активний — translate дельти прив'язуються до сітки (5 мм), rotate — до 15°. Підписи прев'ю показують прив'язані значення.
- **Тест:** Увімкнути snap, потягнути вісь translate → позиція змінюється кроками 5 мм.

### 10. Підтримка touch / жестів
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.cpp` — `touchEvent` / `gestureEvent`
- **Опис:** Додати pinch-to-zoom (два пальці), two-finger orbit, single-finger pan. Використати `QTouchEvent` або `QGestureEvent`.
- **Тест:** На тач-пристрої: pinch для зуму, два пальці для орбіти.

### 11. Експорт скріншоту в'юпорту
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.cpp` — `exportScreenshot()`
- **Опис:** Ctrl+E або кнопка для збереження поточного вигляду як PNG. Використати `QOpenGLWidget::grabFramebuffer()`. Додати множник роздільної здатності (1×, 2×, 4×).
- **Тест:** Ctrl+E, вибрати файл, перевірити що PNG відповідає в'юпорту.

### 12. Рамка / lasso виділення
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.cpp` — `mousePressEvent` / `mouseMoveEvent`
- **Опис:** Shift+перетягування на порожньому місці малює rubber-band прямокутник. На відпуск — вибрати всі фігури чий projected AABB перетинає прямокутник. Для lasso: Ctrl+Shift+перетягування.
- **Тест:** Shift+перетягнути рамку навколо двох кубів → обидва вибрані.

### 13. Повноекранний режим
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.cpp` / `mainwindow.cpp`
- **Опис:** Сховати тулбар, док-вікна, статусбар. Розширити в'юпорт на весь екран. F11 або кнопка.
- **Тест:** F11 → в'юпорт на весь екран. F11 → відновити.

### 14. Анімація камери / згладжування
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportcamera.cpp` / `viewportwidget.cpp` — новий таймер
- **Опис:** Анімувати переходи камери (frame selection, preset views, reset) з easing за ~300 мс. 16 мс таймер з лінійною інтерполяцією або `QEasingCurve::OutCubic`.
- **Тест:** Клікнути preset view → камера плавно рухається до нової позиції.

### 15. Overlay як справжній тулбар
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.cpp` — `updateViewportControls`
- **Опис:** Зараз контроли позиціонуються абсолютно на y=70. Замінити на справжній тулбар з layout, overflow, можливістю перетягування.
- **Тест:** Змінити розмір вікна → контроли перетікають без накладання.

### 16. Frustum culling
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportglrenderer.cpp` — `renderPreview()`
- **Опис:** Обчислити площини frustum з матриці projection × view. Пропускати меші чия bounding sphere повністю поза frustum.
- **Тест:** Наблизитись до малого об'єкта, перевірити що невидимі меші не надсилаються на GPU.

### 17. X-Ray / напівпрозорий режим
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportglrenderer.cpp` — новий шейдер / прохід рендеру
- **Опис:** Перемикач, який рендерить всі об'єкти з прозорістю (alpha=0.3). В GL: задні грані спочатку, потім передні з blending. В SW: зменшити opacity трикутників.
- **Тест:** Увімкнути X-Ray → всі меші напівпрозорі.

### 18. Перемикач snap до сітки
- **Статус:** ❌ Не розпочато
- **Файл:** `viewportwidget.cpp` — новий чекбокс
- **Опис:** Додати явний "Snap" чекбокс поряд з іншими. При активації показувати snap індикатори на сітці (підсвічені точки перетину).
- **Тест:** Увімкнути snap, перетягнути об'єкт → позиція прив'язується до точок сітки.

### 24. Snap до граней/ребер/вершин

## OpenSCAD import/export: повна сумісність дерева

Окремий напрямок, не прив'язаний напряму до в'юпорту: код OpenSCAD має втягуватися в дерево без втрат і генеруватися назад із дерева настільки повно, наскільки це можливо. Поточна реалізація підтримує корисний subset, але не є lossless round-trip.

### Критичні прогалини

1. **Raw/Unknown вузли для збереження непідтриманого коду**
   - **Статус:** ❌ Не розпочато
   - **Файли:** `scenetree.h`, `openscadparser.cpp`, `openscadgenerator.cpp`
   - **Опис:** Додати типи на кшталт `RawStatement`, `RawBlock`, `UnsupportedCall`, щоб parser не викидав незнайомі конструкції. UI може не редагувати такі вузли візуально, але generator має віддати їх назад без втрат.

2. **Збереження коментарів, форматування і debug/background modifiers**
   - **Статус:** ❌ Не розпочато
   - **Файли:** `openscadparser.cpp`, `openscadgenerator.cpp`
   - **Опис:** Коментарі, whitespace, `#`, `%`, `!`, `*` зараз не є повноцінною частиною дерева. Для round-trip треба зберігати trivia/metadata або raw fragments навколо вузлів.

3. **`include<>` / `use<>`**
   - **Статус:** ❌ Не розпочато
   - **Файли:** `scenetree.h`, `openscadparser.cpp`, `openscadgenerator.cpp`
   - **Опис:** Додати AST-вузли або raw-preserved directives для зовнішніх бібліотек. Без цього імпорт реальних OpenSCAD-проєктів втрачає залежності.

4. **Повніші декларації `function` і `module`**
   - **Статус:** ⚠️ Частково
   - **Файли:** `expression.h`, `openscadparser.cpp`, `openscadgenerator.cpp`
   - **Опис:** Модулі та виклики вже є частково, але потрібне повне збереження користувацьких `function name(...) = ...;`, nested module/function declarations, positional/default args і `children()`.

5. **Повна модель OpenSCAD expressions**
   - **Статус:** ⚠️ Частково
   - **Файли:** `expression.h`, `scenestringutils.h`, `openscadparser.cpp`
   - **Опис:** Потрібні first-class vectors/lists/ranges, comprehensions, indexing/slicing, `undef` semantics, string operations і OpenSCAD truthiness. Інакше умови, цикли та параметри можуть імпортуватися з підміною або втратою.

6. **Непідтримані або частково підтримані statements**
   - **Статус:** ❌ Не розпочато / ⚠️ Частково
   - **Файли:** `openscadparser.cpp`, `openscadgenerator.cpp`, `manifoldcsg.cpp`
   - **Опис:** Перевірити й додати round-trip для `echo`, `assert`, `render`, `children()`, `let(...)`, `assign`, `surface`, `import`, `multmatrix`, `search`, `lookup`, `each` та інших OpenSCAD-конструкцій. Якщо немає editable-моделі, зберігати як raw.

7. **Повні параметри операторів**
   - **Статус:** ⚠️ Частково
   - **Файли:** `scenetree.h`, `openscadparser.cpp`, `openscadgenerator.cpp`
   - **Опис:** Не губити `convexity`, локальні `$fn/$fa/$fs`, `resize(auto=...)`, параметри `linear_extrude`, `rotate_extrude`, `projection`, `offset`, `polyhedron` та інші аргументи, які зараз або не моделюються, або генеруються в нормалізованому вигляді.

8. **Polygon/polyhedron round-trip**
   - **Статус:** ⚠️ Частково
   - **Файли:** `shapenode.h`, `openscadparser.cpp`, `openscadgenerator.cpp`, `manifoldcsg.cpp`
   - **Опис:** Зберігати `polygon(paths=...)`, holes, winding, `convexity`; для `polyhedron` зберігати початкові points/faces/convexity без нормалізації індексів, якщо користувач не редагував їх у UI.

### Рекомендована стратегія

- **Editable subset:** конструкції, які дерево реально розуміє і може редагувати візуально.
- **Preserved subset:** усе інше зберігати як raw OpenSCAD, показувати в дереві як read-only/unsupported вузол і генерувати назад без змін.
- **Round-trip тести:** для кожного класу конструкцій додати сценарій `OpenSCAD input -> tree -> generated OpenSCAD`, де перевіряється, що непідтриманий код не зникає, а підтриманий код лишається семантично еквівалентним.
