# Supported OpenSCAD Subset For Tree Roundtrip

This project is not a general OpenSCAD parser yet. `Apply code` is designed to
rebuild the visual tree from the subset generated by the editor plus a small
amount of compatible hand-written code.

The safest rule is simple: keep code close to the editor's generated format.

## Top-Level Structure

Supported at top level:

- line comments that start with `//`
- variable assignments, for example `flange_r = 52;`
- top-level module declarations, for example `module peg(r = 6) { ... }`
- explicit module calls, for example `peg(r = 12);`
- supported groups, transforms, for loops, and primitives

The editor has an internal document root. Generated code does not wrap the
scene in an automatic `scene_model()` module.

Module declarations do not create scene geometry by themselves. A module is
rendered only when a real module call exists in the scene tree. In the graphics
tree, each module card has a non-code call handle that can be dragged into a
valid target to create such a call. The handle itself is never emitted as
OpenSCAD code.

## Supported Blocks

Boolean groups:

```openscad
union() {
    cube([10, 10, 10], center=true);
}

difference() {
    cylinder(h=20, r=10, center=true);
    cylinder(h=30, r=4, center=true);
}

intersection() {
    sphere(r=12);
    cube([20, 20, 20], center=true);
}
```

For `difference()`, the first child is the base and all following children are
cuts. For `intersection()`, all children are masks.

Transform groups:

```openscad
translate([10, 0, 0]) {
    cube([10, 10, 10], center=true);
}

rotate([0, 0, 45]) {
    cylinder(h=20, r=5, center=true);
}

scale([1, 2, 1]) {
    sphere(r=8);
}
```

For loops:

```openscad
for (i = [0 : 5]) {
    translate([i * 10, 0, 0]) {
        cylinder(h=20, r=3, center=true);
    }
}

for (i = [0 : 2 : 10]) {
    cube([4, 4, 4], center=true);
}
```

## Supported Primitives

Preferred generated forms:

```openscad
cube([10, 20, 30], center=true);
sphere(r=12);
cylinder(h=30, r=8, center=true);
```

The tree stores cube size, sphere radius, and cylinder height/radius as editable
expressions when they fit the supported expression syntax.

## Variables And Expressions

Supported expression syntax:

- decimal numbers
- identifiers
- binary `+`, `-`, `*`, `/`
- unary `+` and `-`
- parentheses

Examples:

```openscad
wall = 2;
outer_r = 20 + wall * 2;

module peg(r = outer_r / 2) {
    cylinder(h=30, r=r, center=true);
}
```

Variable support is intentionally smaller than full OpenSCAD:

- scene variables are emitted at top level
- module parameters are emitted in the module signature
- module-local variables are emitted inside the module body
- module calls support named arguments, for example `peg(r = 12);`
- call arguments override module defaults for preview and generated code

The current evaluator is meant for editor controls and preview. It is not a
complete OpenSCAD lexical-scope implementation.

## Module Calls

Supported locations for real module calls:

- directly inside `scene`
- inside `union`, `difference`, or `intersection`
- inside `translate`, `rotate`, or `scale`
- inside `for`
- inside another module body

Example:

```openscad
module peg(r = 6) {
    cylinder(h=30, r=r, center=true);
}

translate([10, 0, 0]) {
    peg(r = 12);
}

peg();
```

The parser no longer creates fallback calls for modules. If a module declaration
has no explicit call, it remains a reusable definition only.

## Known Unsupported OpenSCAD

These constructs are outside the current round-trippable subset:

- `use` and `include`
- nested module declarations
- function declarations
- `let`, `assign`, `if`, and `else`
- list comprehensions and general vector/list expressions
- `children()`
- `$fn`, `$fa`, `$fs`, and other special variables
- positional module arguments in the visual editor workflow
- `minkowski`, `hull`, `offset`, `projection`
- `linear_extrude`, `rotate_extrude`
- `polyhedron`, `import`, `surface`, `text`
- arbitrary named arguments on primitives beyond the generated forms

Unsupported code may be skipped or simplified by the parser. For reliable tree
reconstruction, keep generated block structure and one statement/block header
per line.

## Practical Roundtrip Example

```openscad
flange_r = 52;
pipe_r = 22;

module bolt(r = 4) {
    cylinder(h=18, r=r, center=true);
}

difference() {
    union() {
        cylinder(h=14, r=flange_r, center=true);
        translate([0, 0, 12]) {
            cylinder(h=24, r=pipe_r, center=true);
        }
    }

    for (i = [0 : 5]) {
        rotate([0, 0, i * 60]) {
            translate([40, 0, 0]) {
                bolt(r = 5);
            }
        }
    }
}
```
