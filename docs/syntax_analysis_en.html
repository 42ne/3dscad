OpenSCAD Syntax Analysis — Tree Implementation Effort

Updated: 12 June 2026

This document classifies constructs by architectural layer: expression/parser-only versus tree changes required. For the phased implementation plan with priorities and toolbar coverage, see openscad_feature_roadmap_en.html.

Without Tree Changes parse-time / pure eval

Implemented in expression.h (evaluator) and/or openscadparser.cpp (parser). No new Operation, ShapeNode, or TreeNode::Type required.

SyntaxStatusWhereNotes
Ternary operator a ? b : c ✓ Done expression.h — evalTernary() Fully implemented — evaluates condition, returns true or false branch
Math functions: floor, ceil, round, sign, abs, sqrt, pow, exp, ln, log (log₁₀), sin, cos, tan, asin, acos, atan, atan2, min, max ✓ Done expression.h — evalFunctionCall All fully implemented. Trig correctly uses degrees. log() bug fixed (was returning ln, now log₁₀)
function f(x) = expr; ~ Partial expression.h + parser Definitions stored in functionDefs and called at eval. Recursion not supported
assign(x=…) inline ~ Partial openscadparser.cpp Preprocessed before the main block; lexical scoping not preserved
let(x=…) ~ Partial openscadparser.cpp Treated identically to assign; proper scoping requires a context stack
Block comments /* … */ — Lexer / parser Pure tokenization — no tree impact
$fn ✓ Done expression.h + scenemesh.cpp + manifoldcsg.cpp Fully wired: stored as a Variable node → read by topLevelVariables() → passed as fn to all mesh builders (sphere, cylinder, cone, circle, rotate_extrude, linear_extrude). 0 means use default segment count.
$fa, $fs ~ Partial expression.h Recognised in expressions with correct defaults (12°, 2mm). Not yet used in mesh builders — when $fn=0, fallback uses hardcoded defaults instead of computing segments from $fa/$fs.
$t (animation) ✓ Done expression.h — resolveIdentifier Resolves to 0.0 by default; can be set via m_vars for animation playback
echo() — parser Print or ignore; add to startsWithKnownKeyword
assert() — parser Same as echo; error if condition is false
undef ✓ Done expression.h Treated as 0 in arithmetic
rands() ✓ Done expression.h Returns a real random value via QRandomGenerator in [lo, hi)
len() Stub 0 expression.h Recognised, returns 0; full implementation requires a vector type
norm(), cross() Stub 0 expression.h Recognised, return 0
Array subscript arr[i] Stub 0 expression.h Syntax parsed, returns 0; full lookup requires a vector symbol table
concat(), lookup() — expression.h Limited value without list comprehensions
str(), chr() — expression.h Number/string concatenation; required by text()
color() with alpha and named strings ✓ Done parser Fourth alpha parameter and CSS colour names recognised
cube(size=…, center=…) ✓ Done parser size= (scalar and vector) and center=true supported

Require Tree Changes new Operation / ShapeNode

New Operations — TreeNode::Operation

SyntaxStatusRequiredReason
if(cond) { … } else { … } — Op::Conditional + conditionExpression field Parser evaluates the condition and executes the branch, but no node is created or preserved in the tree. Toolbar icon needed (diamond shape)
offset(r= / delta=) — Op::Offset 2D contour transform; two modes: rounded (r=) and chamfered (delta=)
projection(cut=) — Op::Projection 3D→2D; needs rendering pipeline
intersection_for() — Op::IntersectionFor Loop variant that intersects all iterations instead of unioning them
multmatrix(m) — Op::Multmatrix + 4×4 matrix field Arbitrary affine transform; rarely hand-authored
render(convexity=) — Op::Render Currently flattened; to preserve convexity needs a node
rotate_extrude() ✓ Done Op::RotateExtrude Already implemented
resize([x,y,z]) ✓ Done Op::Resize Already implemented

New Primitives — ShapeNode::Type

SyntaxStatusRequiredReason
text(text, size, font, …) — ShapeNode::Text Font library + mesh generation; parameters: size, font, halign, valign, direction
import("file") — ShapeNode::ImportedMesh File I/O; external mesh storage (STL/DXF/SVG/AMF)
surface("file.dat") — ShapeNode::Surface Image/heightmap → mesh

Architectural Changes

SyntaxStatusProblem
children() in modules — Module needs runtime access to passed children. Requires an Op::Children placeholder node and changes to the entire render model
List comprehensions [for(i=r) e] — Can generate nodes (like for). Parse-time iteration (simpler) or an explicit Op::ListComprehension node
use <file> — Multi-file: separate parse + tree merge; top-level statements NOT executed
include <file> — Same as use, but also imports variables and top-level statements
Nested modules — Module-in-module hierarchy; changes ModuleCall resolution

SyntaxStatusChange

polyhedron() with expressions in points/faces ~ Partial Vertex expressions evaluated via VecExprEvaluator; complex expressions in faces not supported
polygon() with paths= ~ Partial Outer contour read; inner holes (paths) ignored
rotate_extrude(angle=) ✓ Done angle stored in scale.x(); expression in transformExpressions[0]
color() with alpha and named strings ✓ Done Implemented
