OpenSCAD Feature Support Roadmap

Status: 2026-06-12  ·  Project: 3DScad visual editor

This document tracks every OpenSCAD language construct and maps it to its current support level across three layers: parser (can the text be read?), tree node (is there a TreeNode::Operation or ShapeNode::Type?), and toolbar (can the user drag it into the scene?).

Phase 1 High-Impact Language Features

These constructs appear in virtually every non-trivial OpenSCAD file. Missing support causes significant parse-coverage gaps.

1.1 — if / else conditional node

LayerStatusDetail
Parser~ Partial Brace and brace-free forms are parsed; condition is evaluated and the true/false branch is executed inline. The construct vanishes from the tree — it is not preserved as a node.
Tree node✗ Missing No Op::Conditional in SceneTree::TreeNode::Operation; no conditionExpression field; no else-children concept.
Toolbar✗ Missing No toolbar button; no drag-drop slot rules defined.

Implementation sketch:

  1. Add Op::Conditional to SceneTree::TreeNode::Operation enum.
  2. Add QString conditionExpression field to TreeNode.
  3. Convention: first child group = true branch; second child group (optional) = else branch. Use a marker flag bool isElseBranch on a Group child, or split via a reserved separator node.
  4. Parser: instead of branching on evaluation, create a Conditional node and populate both child groups from the parse tree.
  5. Code generator: emit if (cond) { … } else { … }.
  6. Tree renderer: show condition text in the card header ("if (x > 0)").
  7. Toolbar icon: diamond / rhombus shape (classic flowchart decision symbol).
// target tree representation:
if (show_base) {            // → Conditional, conditionExpression = "show_base"
    cube([50, 50, 5]);      //   child group [0] = true branch
} else {
    cylinder(r=25, h=5);    //   child group [1] = else branch (optional)
}

1.2 — Ternary operator a ? b : c

LayerStatusDetail
Expression evaluator (expression.h) ✓ Done evalTernary() is fully implemented — evaluates condition, then lazily returns the true or false branch. Works for any numeric expression.
Tree / toolbar— Inline in expressions; no dedicated node needed.

1.4 — let() proper scoping

LayerStatusDetail
Parser~ Partial Treated identically to assign(): writes into the module-level variable map and does not restore on scope exit. Lexical scoping is not preserved.
Tree / toolbar— OpenSCAD let is expression-level; no tree node needed.

Phase 3 New Group Operations for Toolbar

FeatureParserTree (Op::)ToolbarNotes
offset(r= / delta=) ✗ ✗ ✗ 2D only; two modes: rounded (r=) and chamfered (delta=). Essential companion to polygon/square/text in 2D workflows.
projection(cut=) ✗ ✗ ✗ Collapses a 3D solid to 2D; cut=true gives a cross-section.
multmatrix(m) ✗ ✗ ✗ 4×4 affine matrix transform. Rarely hand-authored; medium priority.
render(convexity=) ✗ ✗ ✗ Forces CSG evaluation; improves preview accuracy. Low visual priority.
intersection_for() ✗ ✗ ✗ Loop variant that intersects all iterations instead of unioning them.
Note on offset: implementing offset() requires a new Op::Offset enum value, a new float field for r/delta, a boolean round flag, and a new toolbar icon. The 2D workflow (square → offset → linear_extrude) is a very common pattern; this has high practical value.

Phase 4 Module System Enhancements

FeatureParserTreeNotes
children() inside a module ✗ ✗ Allows a module to pass child objects through; fundamental for parametric wrappers. Needs a dedicated Op::Children placeholder node.
$children special variable ✗ — Integer count of children passed to a module; used with for(i=[0:$children-1]).
use <file.scad> ✗ ✗ Imports module definitions without executing top-level statements. Requires file-system access and recursive parsing.
include <file.scad> ✗ ✗ Like use but also executes top-level statements.
Recursive module calls ✗ ✗ Requires call-depth guard to avoid infinite loops. Low priority.

Phase 5 Special Variables & Debug Modifiers

FeatureStatusNotes
$fn ✓ Done Fully wired end-to-end: parsed → Variable node → topLevelVariables() → mesh builders. Sphere/cylinder/cone/circle/rotate_extrude/linear_extrude all respect $fn.
$fa, $fs ~ Partial Recognised in expressions with correct defaults (12°, 2mm). Mesh builders do not yet compute segment count from $fa/$fs when $fn=0 — hardcoded defaults used instead.
$t animation variable ✓ Done Resolves to 0.0 by default via resolveIdentifier; can be injected via m_vars to drive animation. Viewport animation timeline integration is separate.
$vpr, $vpt, $vpd ✗ Viewport orientation/translation/distance. Rarely used in printable models.
% (background modifier) ✗ Shows object as translucent ghost; excluded from renders.
# (debug modifier) ✗ Highlights object in preview regardless of parent subtraction.
! (root modifier) ✗ Renders only the prefixed object, ignoring the rest of the file.
* (disable modifier) ✗ Excludes the prefixed object from rendering.

Phase 6 Advanced Expression Features

FeatureStatusNotes
List comprehensions [for(i=r) expr] ✗ Used to build point arrays for polygon/polyhedron dynamically; very common in parametric gear/thread libraries.
Vector/array functions: concat(), each, sum() ✗ Needed for dynamic point list construction.
String type & str(), chr() ✗ Required by text() and echo().
assert(cond, message) ✗ Design-time validation; parsing can silently ignore or log.
echo(…) ✗ Debug output; parsing can silently ignore.
Array subscript with non-literal index ~ Returns 0 arr[i] is parsed and returns 0; full vector lookup requires a proper vector-value symbol table in the expression evaluator.
