Supported OpenSCAD Subset For Tree Roundtrip

This project is not a general OpenSCAD parser yet. Apply code is designed to rebuild the visual tree from the subset generated by the editor plus a small amount of compatible hand-written code.

The safest rule is simple: keep code close to the editor's generated format.

Top-Level Structure

Supported at top level:

  • line comments that start with //
  • variable assignments, e.g. flange_r = 52;
  • vector variable assignments (stored for primitive lookup, not shown in tree), e.g. body_size = [28, 28, 4];
  • top-level module declarations, e.g. module peg(r = 6) { ... }
  • explicit module calls, e.g. peg(r = 12);
  • supported groups, transforms, for loops, and primitives

The editor has an internal document root. Generated code does not wrap the scene in an automatic scene_model() module. Code that was previously wrapped in scene_model() { ... } is silently flattened into the scene root.

Module declarations do not create scene geometry by themselves. A module is rendered only when a real module call exists in the scene tree. In the graphics tree, each module card has a non-code call handle that can be dragged into a valid target to create such a call. The handle itself is never emitted as OpenSCAD code.

Supported Blocks

Boolean groups

union() {
    cube([10, 10, 10], center=true);
}

difference() {
    cylinder(h=20, r=10, center=true);
    cylinder(h=30, r=4, center=true);
}

intersection() {
    sphere(r=12);
    cube([20, 20, 20], center=true);
}

For difference(), the first child is the base and all following children are cuts. For intersection(), all children are masks.

Other block groups

hull() {
    sphere(r=10);
    translate([20, 0, 0]) sphere(r=6);
}

minkowski() {
    cube([20, 20, 20], center=true);
    sphere(r=3);
}

color("red") {
    sphere(r=10);
}

linear_extrude(height = 15) {
    circle(r=8);
}

Note: linear_extrude currently supports only the height parameter. It does not support twist, slices, scale, or center.

Transform groups

translate([10, 0, 0]) {
    cube([10, 10, 10], center=true);
}

rotate([0, 0, 45]) {
    cylinder(h=20, r=5, center=true);
}

scale([1, 2, 1]) {
    sphere(r=8);
}

mirror([1, 0, 0]) {
    sphere(r=8);
}

Transform parameters may be plain numbers or expressions:

wall = 2;
offset = 10;

translate([offset + wall, 0, 0]) {
    cube([10, 10, 10], center=true);
}

rotate([0, 0, 45 * 2]) {
    cylinder(h=20, r=5, center=true);
}

Named argument syntax is also accepted for transforms:

translate(v=[x, y, z]) { ... }
rotate(a=[x, y, z]) { ... }
scale(v=[x, y, z]) { ... }
mirror(v=[x, y, z]) { ... }

Debug Modifiers

The OpenSCAD debug modifiers #, %, !, * are accepted as line prefixes:

  • # — highlight (shown in editor as a marker)
  • % — transparent
  • ! — show only this
  • * — disable the entire statement (children are skipped during parsing)
%translate([10, 0, 0]) {
    cube([5, 5, 5], center=true);
}

*cylinder(h=20, r=3, center=true);
Note: render() (convexity) is recognized and accepted, but its flattening behavior is identical to any other unknown block — the children are imported transparently.

Brace-free single-child shorthand

translate([10, 0, 0])
    cylinder(h=20, r=3, center=true);

rotate([0, 0, 90])
translate([20, 0, 0])
    sphere(r=5);

mirror([1, 0, 0])
    cube([10, 20, 30], center=true);

For loops

for (i = [0 : 5]) {
    translate([i * 10, 0, 0]) {
        cylinder(h=20, r=3, center=true);
    }
}

for (i = [0 : 2 : 10]) {
    cube([4, 4, 4], center=true);
}

Multi-variable for

for (i = [0 : 3], j = [0 : 2]) {
    translate([i * 10, j * 10, 0]) {
        sphere(r=2);
    }
}

intersection_for

intersection_for (k = [0 : 3]) {
    translate([k * 15, 0, 0]) {
        sphere(r=8);
    }
}

let — scoped variable bindings

let (r = x * 2, h = r * 3) {
    cylinder(h=h, r=r, center=true);
}

if / else — parse-time conditional branching

if (x > 5) {
    sphere(r=5);
} else {
    cube(10);
}

else if chains are also supported:

if (x > 10) {
    sphere(r=5);
} else if (x > 5) {
    cube(8);
} else {
    cylinder(h=10, r=3);
}
Note: if/else is evaluated at parse time. Inside module bodies, the condition is ignored and the if-branch is always parsed into the tree (because module parameters only have their default values available at parse time). At the top level (scene scope), the condition is evaluated normally.

Supported Primitives

Preferred generated forms:

cube([10, 20, 30], center=true);
sphere(r=12);
cylinder(h=30, r=8, center=true);
polyhedron(points=[[0,0,0],[10,0,0],[0,10,0],[0,0,10]],
           faces=[[0,2,1],[0,1,3],[1,2,3],[2,0,3]]);

Dimension arguments may also be expressions:

wall = 3;
inner_r = 10;

cube([inner_r * 2, inner_r * 2, wall], center=true);
sphere(r=inner_r + wall);
cylinder(h=wall * 5, r=inner_r, center=true);

Additional accepted forms

PrimitiveAccepted forms
Cube cube([x, y, z]) — center=true is optional, ignored by parser
cube(body_size) — vector variable lookup
cube(n) — single scalar → n × n × n
Sphere sphere(r=12) — named argument
sphere(12) — positional = radius
sphere(d=24) — diameter → 24/2
Cylinder cylinder(h=30, r=8, center=true) — named, any order
cylinder(30, 8) — positional h, r
Polyhedron polyhedron(points=[...], faces=[...]) — editable rows
Points/faces parsed as numeric literals only
AutoFace detects simple two-layer extrusions

Variables And Expressions

Supported expression syntax:

  • decimal numbers (negative via unary minus, scientific notation like 1e5)
  • identifiers referencing previously-declared variables
  • binary +, -, *, /, % (modulo via std::fmod)
  • unary +, -, ! (logical not)
  • comparison: ==, !=, <, >, <=, >= (result 1.0 or 0.0)
  • logical: &&, ||
  • ternary conditional: condition ? true_value : false_value
  • parentheses for grouping
  • math function calls (case-insensitive):
CategoryFunctions
Trigonometry (degrees)sin(x), cos(x), tan(x), asin(x), acos(x), atan(x), atan2(y, x)
Numericabs(x), ceil(x), floor(x), round(x), sign(x), sqrt(x)
Power/exponentialpow(x, y), exp(x), log(x) / ln(x)
Aggregationmin(a, b, ...), max(a, b, ...)
ConstantsPI (π), true (1.0), false (0.0)

Examples

wall = 2;
outer_r = 20 + wall * 2;

module peg(r = outer_r / 2) {
    cylinder(h=30, r=r, center=true);
}

translate([sin(angle) * radius, cos(angle) * radius, 0]) {
    sphere(r=wall + abs(sin(angle * 3)) * 2);
}

// Comparisons and ternary
r = x > 0 ? x * 2 : wall;
if (r > 10) {
    sphere(r=r);
} else {
    cube(r);
}

Expressions can appear in any numeric position:

a = 10;
b = a * 2;

translate([a + 3, 0, b / 4]) {
    cube([a, b, a + b], center=true);
}

for (i = [0 : pow(count, 2) - 1]) {
    translate([sin(i * 360 / count) * PI * 10, 0, 0]) {
        sphere(r=min(3, max(1, i * 0.5)));
    }
}

Variable scoping

  • scene variables emitted at top level
  • module parameters emitted in the module signature
  • module-local variables emitted inside the module body
  • module calls support named arguments: peg(r = 12);
  • call arguments override module defaults for preview and generated code

Module Calls

Supported locations:

  • directly inside scene
  • inside union, difference, or intersection
  • inside translate, rotate, or scale
  • inside for
  • inside another module body
module peg(r = 6) {
    cylinder(h=30, r=r, center=true);
}

translate([10, 0, 0]) {
    peg(r = 12);
}

peg();

Module parameters may have default values or be left without defaults (defaults to 0):

module cap(thickness = 3, r) {
    cylinder(h=thickness, r=r, center=true);
}

The parser no longer creates fallback calls for modules. If a module declaration has no explicit call, it remains a reusable definition only.

Unknown And Unsupported Syntax

Unknown single-line statements are silently skipped. Unknown blocks are transparently flattened — their primitive children are imported as if the wrapper was not present.

Known keywords with unrecognised argument syntax (e.g. cube with a bad arg count, or translate without a valid vector) produce a hard error.

Known Unsupported OpenSCAD

These constructs are outside the current round-trippable subset:

  • use and include
  • nested module declarations
  • function declarations
  • list comprehensions and general vector/list expressions
  • children()
  • $fn, $fa, $fs, and other special variables
  • positional module arguments in the visual editor workflow
  • offset, projection
  • import, surface, text
  • resize(), rotate_extrude
  • render()
  • arbitrary named arguments on primitives beyond the generated forms
  • block comments /* ... */ (single-line // only)
  • if inside modules always takes the true branch (parse-time limitation — module parameter values are only known at call time)

For reliable tree reconstruction, keep generated block structure and one statement/block header per line.

Practical Roundtrip Example

flange_r = 52;
pipe_r = 22;
wall = 2;

module bolt(r = 4) {
    cylinder(h=18, r=r, center=true);
}

difference() {
    union() {
        cylinder(h=14, r=flange_r, center=true);
        translate([0, 0, 12]) {
            cylinder(h=24, r=pipe_r, center=true);
        }
    }

    for (i = [0 : 5]) {
        rotate([0, 0, i * 60]) {
            translate([flange_r - wall * 10, 0, 0]) {
                bolt(r = 5);
            }
        }
    }
}
