Аналіз синтаксису OpenSCAD — оцінка реалізації в дереві

Оновлено: 14 червня 2026

Реалізовано після цього аналізу (14 червня 2026): if / else умовний вузол, тернарний ?:, log() з основою 10, $t, вектор-аумний обчислювач (векторні/діапазонні літерали, v[i], векторна математика, len/norm/cross) з векторними змінними, offset() (Manifold CrossSection) та text() 2D-примітив (контури гліфів Qt, дірки, size/font/halign/valign/spacing, редаговане поле вмісту), projection(cut=) (Manifold slice/project), блочні коментарі /*…*/, echo()/assert() (пропускаються в парсері), concat()/lookup(), $fn підключений до mesh-будівельників, та обчислення сегментів через $fa/$fs. Manifold тепер збирається з CrossSection (Clipper2).
Цей документ класифікує конструкції за архітектурним рівнем реалізації: вираз/парсер проти зміни дерева. Для фазового плану з пріоритетами та колонкою toolbar — дивіться openscad_feature_roadmap_uk.html.

Без змін дерева parse-time / pure eval

Реалізується в expression.h (евалюатор) та/або openscadparser.cpp (парсер). Не потребує нових Operation, ShapeNode або TreeNode::Type.

СинтаксисСтанДе реалізуватиПримітка
Тернарний оператор a ? b : c ✓ Є expression.h — evalTernary() Повністю реалізовано — обчислює умову, повертає відповідну гілку
Математичні функції: floor, ceil, round, sign, abs, sqrt, pow, exp, ln, log (log₁₀), sin, cos, tan, asin, acos, atan, atan2, min, max ✓ Є expression.h — evalFunctionCall Всі реалізовано. Тригонометрія коректно в градусах. Баг log() виправлено (було ln, стало log₁₀)
function f(x) = expr; ~ Частково expression.h + parser Визначення зберігаються в functionDefs і викликаються при eval. Рекурсія не підтримується
assign(x=…) inline ~ Частково openscadparser.cpp Обробляється як препроцесорне розгортання перед основним блоком; лексична область видимості не зберігається
let(x=…) ~ Частково openscadparser.cpp Ідентично assign; правильний scoping потребує стека контекстів
Блочні коментарі /* … */ ✓ Є openscadparser.cpp — normalizedLines() Видаляються регулярним виразом перед обробкою рядків; незакритий /* викидає все далі
$fn ✓ Є expression.h + scenemesh.cpp + manifoldcsg.cpp Повністю підключено: зберігається як Variable-вузол → читається через topLevelVariables() → передається як fn у всі mesh-builders (sphere, cylinder, cone, circle, rotate_extrude, linear_extrude). 0 = стандартна кількість сегментів.
$fa, $fs ✓ Є expression.h + scenemesh.cpp + manifoldcsg.cpp Розпізнаються у виразах з правильними дефолтами (12°, 2mm). При $fn=0 mesh-будівельники обчислюють кількість сегментів з $fa/$fs за алгоритмом OpenSCAD get_fragments_from_r().
$t (анімація) ✓ Є expression.h — resolveIdentifier Повертає 0.0 за замовчуванням; можна задати через m_vars для анімаційного відтворення
echo() ✓ Є openscadparser.cpp Рядки, що починаються з echo(, пропускаються в parseBlock() та в top-level циклі
assert() ✓ Є openscadparser.cpp Той самий механізм пропуску, що й для echo()
undef ✓ Є expression.h Обробляється як 0 в арифметиці
rands() ✓ Є expression.h Повертає справжнє випадкове число через QRandomGenerator у діапазоні [lo, hi)
len() ✓ Є expression.h — evalFunctionCall Повертає кількість елементів вектора; працює з векторним обчислювачем
norm(), cross() ✓ Є expression.h — evalFunctionCall Довжина вектора та 3D векторний добуток повністю реалізовані
Індексування масиву arr[i] ✓ Є expression.h — evalVectorOrRange() Індексація векторних змінних; при виході за межі повертає 0
concat(), lookup() ✓ Є expression.h — evalFunctionCall concat об'єднує значення у вектор; lookup повертає ключ як є (числовий контекст)
str(), chr() ~ Частково expression.h — evalFunctionCall str() заглушка повертає перший числовий аргумент; потрібен рядковий тип у Value
color() з альфою і рядками імен ✓ Є parser Четвертий параметр альфи і рядкові імена кольорів розпізнаються
cube(size=…, center=…) ✓ Є parser Параметри size= (скалярний та векторний) і center=true підтримуються

Архітектурні зміни

СинтаксисСтанПроблема
children() в модулях — Модуль повинен мати доступ до переданих дітей під час рендеру. Потребує вузла-заповнювача Op::Children і зміни всієї моделі рендеру
List comprehensions [for(i=r) e] — Генерують набір нод (як for). Або ітерувати в парсері (простіше), або додати Op::ListComprehension
use <file> — Багатофайловість: окремий парсинг + merge дерева; без виконання top-level операторів
include <file> — Те саме + прямий імпорт змінних і top-level операторів
Вкладені модулі — Ієрархія module-в-module; зміна резолюції ModuleCall
