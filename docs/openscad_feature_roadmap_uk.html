Дорожня карта підтримки функцій OpenSCAD

Стан: 14 червня 2026  ·  Проєкт: 3DScad візуальний редактор

Реалізовано після написання roadmap (14 червня 2026):
  • ✓ if / else — повноцінний вузол Conditional (включно з ланцюгами else-if), парсер/codegen/рендер, кнопка та іконка в тулбарі.
  • ✓ Тернарний ?: і математичні функції; log() виправлено на основу 10; час анімації $t.
  • ✓ Вектор-аумний обчислювач виразів: векторні/діапазонні літерали, індексація v[i], векторна арифметика, справжні len() / norm() / cross() та векторні змінні (points[i], len(points)), протягнуті крізь модель документа.
  • ✓ offset(r= / delta=, chamfer=) — вузол-операція через Manifold CrossSection (Round/Miter/Square), парсер/codegen, тулбар.
  • ✓ text() 2D-примітив — контури гліфів Qt → CrossSection (з дірками), size/font/halign/valign/spacing, працює всередині linear_extrude/offset; на картці пілюлі Sz/Sp та редаговане поле вмісту.
  • ✓ Кнопку resize() увімкнено; намальовано іконки на майбутнє для projection / import.
  • ✓ projection(cut=true/false) — вузол-операція через Manifold CrossSection (зріз на z=0 або повна XY-проєкція), парсер/codegen, тулбар + іконка.
  • ~ Ще відкрито: import(), surface(), children(), list comprehensions, include/use. Manifold тепер збирається з MANIFOLD_CROSS_SECTION=ON (Clipper2), що розблоковує 2D-бекенд.

Цей документ відстежує кожну конструкцію мови OpenSCAD і показує поточний рівень підтримки на трьох рівнях: парсер (чи може текст бути прочитаний?), вузол дерева (чи є TreeNode::Operation або ShapeNode::Type?) та панель інструментів (чи може користувач перетягнути елемент у сцену?).

Позначення: ✓ Є повністю реалізовано   ~ Частково реалізовано неповністю   ✗ Відсутнє не реалізовано   — не застосовується

Фаза 1 Критично важливі мовні конструкції

Ці конструкції присутні практично в кожному нетривіальному файлі OpenSCAD. Відсутня підтримка призводить до суттєвих прогалин у покритті парсером.

1.1 — Умовний вузол if / else

РівеньСтанДеталі
Парсер~ Частково Обидві форми (з дужками і без) парсяться; умова обчислюється і вибирається відповідна гілка. Проте конструкція зникає з дерева — як вузол вона не зберігається.
Вузол дерева✗ Відсутнє Немає Op::Conditional в перечисленні SceneTree::TreeNode::Operation; немає поля conditionExpression; немає концепції else-гілки.
Панель інструментів✗ Відсутнє Немає кнопки на toolbar; не визначені правила drag-drop-слотів.

План реалізації:

  1. Додати Op::Conditional в перечислення SceneTree::TreeNode::Operation.
  2. Додати поле QString conditionExpression до TreeNode.
  3. Домовленість: перша дочірня група = гілка true; друга дочірня група (опціонально) = гілка else. Використовувати прапорець bool isElseBranch на дочірньому Group-вузлі.
  4. Парсер: замість обчислення і переходу — створювати Conditional-вузол і заповнювати обидві дочірні групи з дерева розбору.
  5. Генератор коду: виводити if (cond) { … } else { … }.
  6. Рендерер дерева: відображати текст умови в заголовку картки ("if (x > 0)").
  7. Іконка toolbar: ромб — класичний символ рішення у блок-схемах.
// цільове представлення в дереві:
if (show_base) {            // → Conditional, conditionExpression = "show_base"
    cube([50, 50, 5]);      //   дочірня група [0] = гілка true
} else {
    cylinder(r=25, h=5);    //   дочірня група [1] = гілка else (опціонально)
}

1.4 — Правильна область видимості let()

РівеньСтанДеталі

Фаза 5 Спеціальні змінні та модифікатори налагодження

ФункціяСтанПримітки
$fn ✓ Є Повністю підключено: парситься → Variable-вузол → topLevelVariables() → mesh-builders. Сфера/циліндр/конус/коло/rotate_extrude/linear_extrude — всі підтримують $fn.
$fa, $fs ~ Частково Розпізнаються у виразах з правильними дефолтами (12°, 2mm). Mesh-builders не обчислюють кількість сегментів з $fa/$fs при $fn=0 — використовуються hardcoded дефолти.
Анімаційна змінна $t ✓ Є Повертає 0.0 за замовчуванням через resolveIdentifier; може бути задано через m_vars. Підключення до таймлайну viewport — окрема задача.
$vpr, $vpt, $vpd ✗ Орієнтація/зміщення/відстань viewport. Рідко використовується у моделях для друку.
Модифікатор % (фон) ✗ Показує об'єкт напівпрозорим привидом; виключається з рендеру.
Модифікатор # (налагодження) ✗ Підсвічує об'єкт у попередньому перегляді незалежно від операції батьківського вузла.
Модифікатор ! (корінь) ✗ Рендерить лише позначений об'єкт, ігноруючи решту файлу.
Модифікатор * (вимкнення) ✗ Виключає позначений об'єкт із рендеру.
